# smartclass-buct 技术开发文档

> 版本：2026-10-19
> 对应代码：`src/smartclass/`（约 4k 行 Python）
> 读者：需要改代码、排查问题、扩展平台适配的开发者。

## 1. 目的与范围

本文档描述 `scls` 的内部实现：

- 平台访问层（登录、列表、取流、下载）；
- 数据模型与目录布局；
- 处理流水线（ASR / OCR / 归纳 / 压缩）；
- 并发调度、缓存、幂等；
- 状态、锁、日志、定时任务；
- 迁移命令与测试策略。

不描述平台自身的业务规则，也不鼓励绕过权限。所有平台访问都基于本人已登录的
Playwright 会话。

## 3. 总体架构

```
┌────────────────────────────────────────────────────────────────────┐
│ CLI (cli.py)                                                       │
│  login / list / run / resume / daily / bench / regroup /           │
│  migrate-layout / prune / schedule / asr / slides / digest         │
└───────────────┬────────────────────────────────────────────────────┘
                │
                ▼
┌──────────────────────────────┐      ┌─────────────────────────────┐
│ 发现与下载（主线程）          │      │ 处理（工作线程）             │
│ browser.py  登录态            │      │ _process_lecture            │
│ discover.py 列表/翻页         │─────▶│  ├─ audio.extract_audio     │
│ streams.py  取流              │ yield│  ├─ asr.transcribe          │
│ download.py 下载              │      │  ├─ vision.scan             │
└──────────────────────────────┘      │  ├─ merge                   │
                                      │  ├─ digest                  │
                                      │  └─ videoops (后台压缩)      │
                                      └──────────────┬──────────────┘
                                                     │
                                      ┌──────────────▼──────────────┐
                                      │ scheduler.py 全局网关线程池  │
                                      │  ASR 块 / OCR 批 / 归纳      │
                                      └─────────────────────────────┘
```

关键设计：

1. **Playwright 只在主线程**。下载流水线用生成器实现：主线程继续发现/取流/下载
   第 N+1 节，工作线程处理第 N 节。工作线程只碰文件、`requests`、ffmpeg。
2. **网关请求统一走有界线程池**。ASR 块、OCR 批都提交到 `scheduler.gateway_map`，
   结果按 index 回填，保证落盘顺序不变。
3. **所有阶段幂等**。分块 JSON、`slides.txt`、`homework_*.md`、`notes_*.md`
   都存在即跳过；`--force` 才重跑。

## 5. 平台访问层

### 5.1 浏览器与登录态

`browser.browser_session(cfg, headed)`：

- `pw.chromium.launch_persistent_context(user_data_dir=profile_dir, headless=not headed)`
- 参数 `--disable-blink-features=AutomationControlled`
- viewport 1440×900
- 若配置了 `storage_state`，先注入 cookie 与 localStorage
  （本站鉴权还依赖 `localStorage` 里的 `platform_token` / `csrkKeyNew`，
  只注入 cookie 不够）

登录检测：

- `LOGIN_ITEM = "li.login_area"`：未登录时该区域可见，已登录时隐藏。
- `is_logged_in(page)`：访问 `/Default.aspx`，等顶部导航渲染后判断。
- 找不到该区域（跳转到统一身份认证页、页面未渲染）时**保守判为未登录**。
- `ensure_logged_in(page, cfg, headed, interactive)`：
  - 已登录 → 直接返回；
  - 无头且失效 → 抛 `RuntimeError`，提示 `scls login`；
  - 有头且交互 → 每 2 秒**只读检测**当前页面，**绝不 `page.goto`**，
    避免刷掉用户正在操作的登录页；超过 `login_timeout` 抛 `TimeoutError`。

`cookie_header(ctx)` 把上下文 cookie 拼成 `Cookie` 头，供 `requests` 下载使用。

### 5.2 列表接口与 `csrkToken`

平台列表接口：

```
/Webapi/V1/Video/GetMyVideoList
    ?csrkToken=<页面 JS 生成>
    &StartDate=YYYY-MM-DD
    &EndDate=YYYY-MM-DD
    &PageNumber=N
    &PageSize=50
```

关键事实（实测）：

- `csrkToken` **不是一次性的**：在同一个页面会话内可以复用。
- `PageSize` 服务端上限 50（请求 200 只返回 50）。
- 响应形如 `{"Value": {"TotalCount": N, "Data": [...]}, "Success": true}`。

因此 `discover` 不直连接口，而是：

1. `ApiCapture` 挂 `page.on("response")`，只收
   `GetPublicVideos` / `GetMyVideoList` / `GetVideos` 的 200 JSON；
2. 打开 `/UserSpace/CourseList.aspx`，让页面自己发一次请求；
3. 用截到的 URL 作为模板，`_with_params` 改写
   `StartDate/EndDate/PageNumber/PageSize`；
4. `ListPager.fetch` 在页面上下文里 `fetch(url, {credentials:'include'})`，
   **复用 token 翻页到 `TotalCount`**；
5. `sessions_from_payloads` 宽容解析字段（大小写/别名），
   `_walk_items` 递归找「既像 ID 又有标题/时间」的字典。

兜底链：

1. 默认页签可能是「公开视频」→ `click_my_related` 切到「与我相关」
   （已截到 `GetMyVideoList` 就不切，省一次点击和 4 秒等待）；
2. 截不到接口 → `sessions_from_dom(page)` 解析 DOM；
3. 翻页接口不可用 → 退回只解析页面已加载的一页；
4. 仍不覆盖区间 → `set_date_range` 填页面日期控件后重取。

`_warn_empty_days` 会把区间内「工作日却没有任何录播」的日期显式列出来，
避免用户误以为工具漏抓（实际可能是放假/停课/录制失败）。

### 5.3 课时解析与课程匹配

`Session`：

```python
@dataclass
class Session:
    new_id: str
    text: str = ""
    date: str = ""
    start: str = ""     # HH:MM:SS
    end: str = ""
    course: str = ""
    raw: dict = field(default_factory=dict)

    @property
    def slot(self) -> str:
        return f"{self.start[:5].replace(':','')}-{self.end[:5].replace(':','')}"
```

字段别名：

- ID：`NewID/NewId/newId/newid/Id/VideoID/VideoGuid`
- 标题：`Title/title/Name/VideoName/ScheduleName`
- 课程：`CourseName/courseName/Course/SubjectName`
- 教师/教室：`TeacherName/SpeakerName`、`ClassroomName/Room/...`
- 时间：`StartTime/BeginTime/StartDate`、`EndTime/StopTime/EndDate`

课程名匹配 `normalize_key`：

- 全角括号 → 半角；
- 罗马数字 `Ⅰ/Ⅱ/...` → `i/ii/...`；
- 去空白、转小写；
- 先按折叠键包含匹配，再退回原文包含。

### 5.4 取流

`streams.fetch_streams(cfg, page, new_id)`：

1. 打开 `/PlayPages/Video.aspx?NewID=<new_id>`；
2. 每 1.5 秒查一次 `<video>` / `<source>` 的 `src`；
3. 播放器初始化成功 → 直接得到机位 URL；
4. 播放器没起来（页面里常见 8 个空 `<video>`）→ `VodSniffer` 监听页面请求，
   从 `.../<scheduleId>/1/000.jpg`、`Caption.json`、`srt.js` 里提取 VOD 目录前缀：

   ```
   https://buctvodNNN.smartclass.cn:8010/vod4/YYYY/MM/DD/<scheduleId>/1/
   ```

5. 拼 `VGA.mp4` / `Video1.mp4`，用 `remote_size`（HEAD）验证存在。

机位含义：`vga` = 课件/屏幕，`video1` = 教室摄像机。

### 5.5 下载

`download.download(url, dest, cookie, force)`：

- `remote_size` 先 HEAD 取总大小（SSL EOF 会重试 3 次，间隔 1.5/3/4.5s）；
- 已存在且大小匹配 → 跳过；
- 写 `<dest>.part`，支持 `Range: bytes=<pos>-` 续传；
- 1 MiB 一个 chunk，每 5% 打一次进度；
- 完成后 `part.replace(dest)`；
- 服务端不支持续传（返回非 206）→ 从头写。

`_prepare_lecture` 对同一小节的多个机位用 `scheduler.parallel_map(..., workers=downloads)`
并发下载。

**本地优先**：如果目标视频已存在，先认本地，不再取流/HEAD。
这样已下载的课可以离线重跑，也不会因为 VOD 主机一次 SSL 抖动判成「没有录播」。

## 6. 数据模型

### 6.1 整课分组

`grouping.group_sessions(sessions, max_gap_minutes)`：

- 按 `(course 或 course_key(text), date)` 分桶；
- 桶内按 `start` 排序；
- 相邻小节 `start - prev.end > max_gap` → 切分成新整课；
- 结果按 `(date, start_min, course)` 排序。

`Lecture` 属性：

- `start_min/end_min`：当天分钟数；
- `start/end`：`HH:MM`；
- `span`：`HHMM-HHMM`（目录/uid 用）；
- `label`：`08:00-10:30（3 小节）`。

### 6.2 目录对象

`RunDir`（小节级）：

```python
@dataclass
class RunDir:
    root: Path
    uid: str = ""   # 2026-10-16_0800-0845；空=旧布局
```

- `homework_path` → `homework_<uid>.md`（uid 为空则 `homework.md`）
- `notes_path` → `notes_<uid>.md`
- `videos/ audio/ transcript/ frames/`、`meta.json`、`slides.txt`、`full_transcript`

`LectureDir`（整课级）：

```python
@dataclass
class LectureDir:
    root: Path
    uid: str = ""   # 2026-10-16_0800-1030；空=旧布局
```

- `parts_dir` = `root/parts`；
- `part(slot)` → `RunDir(root/parts/<slot>, uid=<date>_<slot>)`；
- `homework_path` / `notes_path` 始终带 uid 后缀；
- `meta_path` / `transcript_path` / `slides_path` 采用**冲突感知**命名：
  - 如果 `root/lecture.json` 已存在且 `uid` 不同（同一天第二节），
    自动改用 `lecture_<uid>.json` / `transcript_<uid>.txt` / `slides_<uid>.txt`；
  - 第一节继续用无后缀文件。

这样既满足「日期目录下直接放内容」，又能容纳同一天多节整课。

### 6.3 `lecture.json`

```json
{
  "course": "物理化学(Ⅰ)",
  "date": "2026-10-16",
  "start": "08:00:00",
  "end": "10:30:00",
  "span": "0800-1030",
  "uid": "2026-10-16_0800-1030",
  "layout": "flat",
  "parts": [
    {"new_id": "...", "start": "08:00:00", "end": "08:45:00",

  "timings": {"audio": 25.1, "asr": 65.2, "ocr": 98.4,

```

`save_meta` 会自动补 `uid` 和 `layout`。

## 7. 处理流水线

### 7.1 控制流

`cmd_run`：

```
load_config → _resolve_range → solo_lock → _run_pipeline
```

`_run_pipeline`：

```
scheduler.configure(cfg)

# 本地续跑（resume）
if from_dir:
    jobs = _jobs_from_local_dir(...)
    逐个 _process_lecture(...)
    return

# 联网
gen = _iter_lectures(cfg, args, date_from, date_to)
if dry_run: 消费 gen，打印，返回
with ThreadPoolExecutor(max_workers=1) as pool:
    for job in gen:
        pool.submit(_process_lecture, cfg, *job, args)
    等所有 future
```

`_iter_lectures` 是一个生成器：

```python
with browser_session(cfg, headed=args.headed) as (ctx, page):
    ensure_logged_in(...)
    sessions = discover(...)
    sessions = filter_sessions(...)
    lectures = group_sessions(...)
    for lec in lectures:
        lec_dir = lecture_dir_for(...).ensure()
        videos = _prepare_lecture(...)   # 取流 + 下载
        lec_dir.save_meta({...})
        yield lec, lec_dir, videos
```

- 生成器内部始终在主线程，Playwright 不跨线程；
- 主线程 `yield` 后继续下载下一节；
- 工作线程处理上一节；
- `finally: gen.close()` 保证浏览器上下文一定关闭。

### 7.2 `_process_lecture`

```
keep = args.keep_video or cfg.retention.keep_video
compress_pool = ThreadPoolExecutor(max_workers=cfg.concurrency.compress)

for part in lec.sorted_parts():
    video = videos[part.slot]
    mp3 = audio.extract_audio(video, parts/<slot>/audio/<name>.mp3)

    # ASR 与「抽帧+OCR」并行
    with ThreadPoolExecutor(max_workers=2) as pex:
        fa = pex.submit(asr.transcribe, ...)
        fo = pex.submit(vision.scan, ...)
        stats.asr += fa.result()
        stats.ocr += fo.result()

    # 音频/关键帧已就绪 → 压缩丢后台
    compress_pool.submit(apply_retention, ...)

refs = _part_refs(...)
merge_transcripts(refs, lec_dir.transcript_path, title)
merge_slides(refs, lec_dir.slides_path, title)

# 作业与笔记并行
scheduler.parallel_map(lambda fn: fn(), [build_homework, build_notes], workers=2)

# join 压缩任务
for fut in compress_futs: stats.compress += fut.result()

# 写 timings 到 lecture.json
```

要点：

- 每个小节的 `do_asr` / `do_ocr` 用默认参数捕获当前 `part/video/mp3`，
  避免闭包晚绑定；
- `stats` 里的 `asr/ocr/compress` 是**各阶段耗时之和**（可能重叠），
  `total` 是墙钟；
- 压缩失败不会中断整课，只打印 `[压缩] 失败：...`。

### 7.3 合并与时间戳

`merge.shift_timestamps(text, base_seconds)`：

- 正则 `[(\d{1,2}):(\d{2})]`；
- 加上小节在整课中的起点秒数；
- 输出仍然是 `[mm:ss]`。

`_part_text` 优先读 `transcript/part_NNN.json`（能拿到块内 `offset`），
再退回 `full.txt`。

`merge_transcripts` 在每个小节前插入 `【08:00-08:45】` 分隔头；
`merge_slides` 同理。

### 7.4 幂等矩阵

| 产物 | 判定 | 重跑行为 |
|---|---|---|
| `audio/<name>.mp3` | 文件存在且 mtime ≥ 源视频 | 跳过 |
| `audio/chunks/part_NNN.mp3` | 文件存在且非空 | 跳过 |
| `transcript/part_NNN.json` | JSON 可解析且 `text` 非空 | 跳过 |
| `frames/f_*.jpg` | 目录里已有 jpg | 跳过抽帧 |
| `slides.txt` | 文件存在且非空 | 跳过 OCR |
| `homework_<uid>.md` | 文件存在且非空 | 跳过归纳 |
| `notes_<uid>.md` | 同上 | 跳过 |
| `meta.json.retained` | 存在且非 `--force` | 跳过压缩/删除 |

`--force` 会绕过以上判定；`resume` 的 `--force` 只重跑本地处理，不下载。

## 8. 并发与调度

`src/smartclass/scheduler.py`：

```python
_pool: ThreadPoolExecutor | None
_size: int
_lock: threading.Lock

configure(cfg)       # 按 [concurrency] gateway 初始化全局池
gateway_map(fn, items, label="") -> list
parallel_map(fn, items, workers=2, label="") -> list
shutdown()
```

`_run_all`：

- 为每个 item 提交一个 future；
- `as_completed` 收集结果，按输入 index 写回 `out`；
- 单个任务异常不取消其他任务（缓存尽量补齐），最后统一抛第一个；
- 多个异常时抛 `RuntimeError("N 个任务失败，首个：...")`；
- `label` 每完成一项打印 `[n/N]`。

`parallel_map` 始终创建**独立**线程池，不占用网关池名额——压缩/下载可能与
转写同时进行。

### 8.1 避免自锁

- 网关池只跑**单个 HTTP 请求**（`_post_gateway` / `_ocr_batch` / `_chat`）。
- 不要把 `transcribe()` / `scan()` 本身提交到网关池：它们内部还会
  `gateway_map`，池满时会自锁。
- ASR 与 OCR 的并行用 `_process_lecture` 里的独立 2 线程池，
  与网关池是两套线程。

### 8.2 顺序与异常

- ASR 结果按 chunk index 回填，`full.txt` 顺序不变；
- OCR 结果按 batch 号排序后写 `slides.txt`；
- 一个块/批失败 → 其他继续，最后抛错；成功的块已落盘，重跑只补失败块。

### 8.3 限流

`asr._transcribe_segment`：

- 429/503 → 同一模型随机退避 `3~8s`，最多 3 次；
- 其他 4xx/5xx → 直接换模型；
- 空结果/复述说明 → 同模型最多 2 次，然后换模型；
- 所有模型都 429 → 不再对半切分（切了也会 429），错误信息提示
  「把 `[concurrency] gateway` 降到 2」。

实测（10 分钟块）：

| 模型 | 并发 1 | 并发 2 | 并发 4 |
|---|---|---|---|
| `gemini-3-flash` | 10.1s | 6.1s | 6.0s |
| `gemini-3.8-flash-high` | 49.0s | 20.3s | 17.2s |

并发 2 基本吃满 flash；4 不吃亏，给 OCR 同时跑留余量。

## 9. ASR 子系统

### 9.1 音频

`audio.extract_audio`：

```
ffmpeg -y -i <video> -vn -ac 1 -ar 16000 -c:a libmp3lame -b:a 32k <mp3>
```

`audio.split_chunks`：

- 按 `chunk_seconds`（默认 600）切块；
- `-ss <offset> -t <chunk_seconds> -i <mp3>`（快速 seek）；
- 输出 `audio/chunks/part_NNN.mp3`；
- 返回 `Chunk(path, offset, dur)` 与总时长。

### 9.2 提示词

`SYS_PROMPT` 要求：

- 逐字转写，不总结、不省略、不翻译；
- 每 30~60 秒一个 `[mm:ss]`；
- 作业/实验报告/提交要求/截止/分组/字数/格式/评分标准原样完整转写；
- 听不清用 `???`；
- 严禁复述说明；整段静音只回 `SILENCE`。

`_ECHO_MARKERS` 命中且文本 <500 字 → 判为「串味」，重试/换模型。

### 9.3 请求

`_post_gateway(cfg, model, audio_path, offset, duration)`：

- 读 mp3 → base64；
- `messages`：system + user（文本 + `input_audio`）；
- `max_tokens = cfg.asr.max_tokens`，`temperature=0`；
- 显式判断 `choices` 是否为空（网关可能返回 HTTP 200 + `choices: []`）；
- 用 `_clean_text` 去掉快模型在汉字间插的空格；
- 返回 `(text, 失败原因)`。

### 9.4 降级链

```
主模型（最多 2 次）
  → fallback_models 逐个（每个最多 2 次）
  → 对半切开重试（最多 3 层，min_split_seconds=45）
  → 抛 RuntimeError
```

默认：

```toml
model = "gemini-3-flash"
fallback_models = ["gemini-3.8-flash-high", "gemini-3.5-flash-lite", "gemini-3.1-flash-lite"]
```

### 9.5 缓存与输出

- 每块写 `transcript/part_NNN.json`：`{index, offset, dur, text}`；
- `full.txt` 头部写 `# 转写 <audio> total=... provider=...`；
- 每块前写 `===== [mm:ss +Nm] =====`。

缺块/空块会在重跑时自动补。

## 10. 课件 OCR 子系统

### 10.1 抽帧

`audio.extract_frames`：

```
ffmpeg -y -i <video> -vf "fps=1/45,scale=1280:-1" -q:v 3 <frames>/f_%03d.jpg
```

- 默认 45 秒一张，宽度 1280；
- 已存在 jpg 则跳过。

### 10.2 去重

`audio.dedupe_frames(frames, threshold=3)`：

- Pillow 打开 → 灰度 → 16×16 → 横向差分 dHash（256 bit）；
- 与**上一张保留帧**比汉明距离；
- `distance <= threshold` → 丢弃；
- 返回 `[(原始序号, Path)]`，时间戳标签仍用「原始序号 × interval」；
- 缺少 Pillow 时打印提示并返回全量。

实测（2026-10-16 三个小节）：66→26、65→62、65→54，平均省约 27%。

### 10.3 批 OCR

`vision.scan`：

- 每 `batch`（默认 8）张图一批；
- 每张前加 `[mm:ss] filename`；
- 两个提示词：
  - `PROMPT_ASSIGNMENT`：只抄作业/提交/评分相关；
  - `PROMPT_FULL`：抄全部文字。
- 批任务 `scheduler.gateway_map` 并发；
- 结果按批号排序，写 `slides.txt`，每批带 `########## BATCH n [start..end] ##########`；
- `_ocr_batch` 对空 choices/空文本/HTTP 错误最多重试 4 次（3~12s 退避）。

## 11. 归纳子系统

`digest.py`：

- `HOMEWORK_TEMPLATE`：7 个小节（形式/范围/框架/附带任务/下发资料/时间/存疑）；
- `NOTES_TEMPLATE`：按章节输出要点/关键概念/时间戳；
- 规则：只能依据材料，不得编造；每条结论附 `> 原文`；
- `KEYWORDS` 命中原文行作为「证据区」，最多 400 行；
- `_chat` 使用 `cfg.digest.model` / `max_tokens`，空 choices 保护；
- `build_homework` / `build_notes` 在 `_process_lecture` 里用
  `scheduler.parallel_map(..., workers=2)` 并行。

## 12. 视频压缩

`videoops.compress_video`（编码器由 `hwaccel.detect` 决定，默认 `auto`）：

```
# CPU（探测不到 GPU，或 video_encoder = cpu）
ffmpeg -y -nostdin -i <src> [-vf fps=N,scale=-2:H] \
  -c:v libx264 -crf 33 -preset veryfast -movflags +faststart -c:a copy <tmp>

# Intel GPU（video_encoder = qsv / auto 探测命中）
ffmpeg -y -nostdin -i <src> \
  -c:v h264_qsv -global_quality 30 -preset veryfast -movflags +faststart -c:a copy <tmp>
```

- `video_encoder=auto`（默认）依次探测 qsv → nvenc → amf（各跑一次 3 帧黑场测试编码，
  毫秒级），都不行退回 `libx264`；探测结果进程内缓存，不会每节视频重复探测；
- QSV 的 `-global_quality`（ICQ）与 x264 的 CRF 不是同一标尺，统一按 `gq = crf - 3` 映射
  （原始课件实测 gq30 ≈ crf33 的体积，SSIM 0.985 vs 0.981 反而略高）；
- 硬件编码在真实文件上失败时，`demote()` 让本进程退回 CPU 重试一次，不中断整批处理；
- 只加速编码不加速解码：实测 `-hwaccel d3d11va` 对 1080p 课件流反而更慢
  （编码 657 vs 804 fps、抽帧 6.2s vs 1.0s），软解 + 硬编码才是最优组合；
- `-movflags +faststart` 把 moov 原子移到文件头，Web 播放器可边下边放、随时拖动进度条；

`apply_retention`：

- `compressed` → `compress_video`
- `none` → 有音频+帧备份才删，否则保留
- `original` → 不动

`_process_lecture` 把压缩提交到后台池，与下一小节重叠。
`cmd_prune` 对历史数据补做，跳过 `_state/_profile/_手工初版` 等目录。

## 13. 状态、锁与日志

### 13.1 文件锁

`state.solo_lock(cfg, name="run")`：

- 锁文件 `data/_state/<name>.lock`，内容为 PID；
- 已有锁且 PID 存活 → 抛 `Busy`（CLI 退出码 3）；
- PID 不存在 → 视为 stale，删除重写；
- 退出时删除锁。

**Windows 陷阱**：`os.kill(pid, 0)` 在 CPython/Windows 上不是探活，而是
`TerminateProcess(handle, 0)`，会**以退出码 0 杀掉进程**。因此
`state._pid_alive` 在 Windows 上用：

```
OpenProcess(SYNCHRONIZE | PROCESS_QUERY_LIMITED_INFORMATION)
GetExitCodeProcess
WaitForSingleObject(handle, 0)
```

### 13.2 登录失效留痕

`mark_login_needed(cfg, detail)`：

- 写 `data/_state/login-needed.txt`（时间 + 原因 + 提示）；
- 弹一个 Windows 通知（`System.Windows.Forms.NotifyIcon`，失败忽略）。

`daily` 捕获含「登录」的 `RuntimeError` → 写留痕 → 返回 2。

### 13.3 日志

`tee_log(cfg, tag="daily")`：

- 文件 `data/_logs/<日期>_<tag>.log`；
- 用 `_Tee` 同时写 stdout/stderr 和文件；
- 每行 flush。

`schedule` 另写 `data/_logs/schtasks.log`（wrapper 重定向）。

## 14. 迁移

### 14.1 `regroup`（第一阶段 → 整课包）

旧布局：

```
data/<课程>/<日期>/<时段>/meta.json
```

新布局：

```
data/<课程>/<日期>/parts/<时段>/
```

`regroup`：

- `_collect_old_sessions` 找有 `meta.json`、无 `parts/` 的目录；
- `group_sessions` 分组；
- 移动小节目录到 `parts/<slot>`；
- 写 `lecture.json`（含 uid/layout）；
- 合并转写/课件文字；
- 可选重新归纳。

### 14.2 `flatten`（整课包 → 扁平）

旧布局：

```
data/<课程>/<日期>/<时段>/{lecture.json,homework.md,notes.md,transcript.txt,slides.txt,parts/}
```

新布局：

```
data/<课程>/<日期>/{homework_<uid>.md,notes_<uid>.md,transcript.txt,slides.txt,lecture.json,parts/}
```

`flatten`：

1. 遍历 `base/<课程>/<日期>/`，找 `<时段>/lecture.json`；
2. `_move_parts` 把 `parts/<slot>` 上移（目标已存在则报错并保留原目录）；
3. `_move_file` 移动文本文件：
   - `homework.md` → `homework_<date>_<span>.md`
   - `notes.md` → `notes_<date>_<span>.md`
   - `transcript.txt` / `slides.txt` → 无后缀或 `_<uid>`（冲突时）
4. 写 `lecture.json`（`uid`/`layout=flat`），删旧 `lecture.json`；
5. 空目录 `rmdir`，有未识别文件则保留并 warn；
6. `_rename_part_digests` 把小节级 `homework.md`/`notes.md` 也改成
   `homework_<date>_<slot>.md` / `notes_<date>_<slot>.md`。

冲突规则：

- 同一日期第一节占 `lecture.json` / `transcript.txt` / `slides.txt`；
- 后续节检测到 plain `lecture.json` 的 uid 不同 → 用 `_<uid>` 后缀；
- `homework`/`notes` 永远带 uid 后缀。

幂等：迁移完旧 `<时段>/` 目录消失，再跑返回 `(0, 0)`。

### 14.3 备份

`migrate-layout` 本身不自动备份；本次迁移前人工备份在
`data/_state/backup-flatten-20261019/`（仅文本，约 1MB）。
`_state` 已被 `resume`/`prune`/`flatten` 的扫描跳过。

## 18. 性能

### 18.1 基线（改造前）

5 节整课 / 15 小节 / 675 分钟音频：

| 阶段 | 单小节 | 合计 | 占比 |
|---|---|---|---|
| ASR（6 块 × ~34s） | 168s | 42 min | 40% |
| OCR（9 批 × ~10s） | 88s | 22 min | 21% |
| 视频压缩 | ~96s | 25 min | 24% |
| 抽帧 | 48s | 12 min | 11% |
| 抽音频+切块 | ~15s | 4 min | 4% |

### 18.2 改造后

- ASR 块并发 + 换 `gemini-3-flash`：42 min → 8~10 min；
- OCR 批并发 + 去重：22 min → 5~7 min；
- 抽帧与 ASR 并行：12 min → 隐藏；
- 压缩后台化：25 min → 5~8 min（或与处理重叠）；
- 下载并发 + 流水线：10~15 min → 5~6 min 且与处理重叠；
- **GPU 编码（2026-10-22，Intel Arc B390）**：45 分钟小节 104s → **47~51s**，
  CPU 占用几乎归零（QSV 固定功能单元），且与 OCR/归纳互不抢核。

实测单节整课（3 小节，1080p，不含压缩）**146 秒**；
原来 16~18 分钟。含两小节 GPU 压缩的完整一轮约 4~5 分钟。
### 18.3 调优

```powershell
scls bench --run "<已缓存小节>" --stage asr,ocr --concurrency 1,2,4,6
```

- 并发 2 通常吃满 `gemini-3-flash`；
- 出现 429 → `gateway=2`；
- 想更快：`video_fps=10`（编码快 2~3 倍）；
- 想完全串行：`gateway=1, downloads=1, compress=1, pipeline=false`；
- 无 GPU/驱动异常：`[retention] video_encoder = "cpu"` 显式退回 x264，或指定
  `"qsv" / "nvenc" / "amf"` 强制某一路；硬件编码失败会在本进程内自动降级。

## 21. 技术债与限制

- `discover` 依赖平台页面结构/接口字段；改版需要更新 `CAPTURE_URL_HINTS`、
  `*_KEYS`、`RE_VOD_BASE`。
- `csrkToken` 复用是实测行为，不保证永久成立；失效会退回 DOM/日期控件。
- 并发上限依赖本地网关；没有全局自适应降并发（只有 429 退避 + 提示）。
- `--force` 会重新下载视频；如果只想重跑处理，应使用 `resume --force`。
- 抽帧去重是启发式，极端滚动课件可能误合并；可关。
- Windows 计划任务依赖桌面会话，不是真正的服务级无人值守。
- 迁移命令假定同一日期下小节 slot 不冲突；冲突时保留原目录并报错，不自动合并。
- ASR/OCR 的转写质量取决于网关模型；没有本地质量评估，只提供 `bench` 的
  字数/相似度参考。
